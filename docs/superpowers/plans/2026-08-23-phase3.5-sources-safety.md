# drophoto Phase 3.5 — Sources, safety deny-list, progress, revert — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Never index or move anything that isn't the user's photos: scans run only over confirmed per-drive **sources** chosen from an auto-detected list, a hard deny-list keeps system/app content out, the walk phase shows visible progress, the gallery stops showing broken tiles, and every organize job can be reverted.

**Architecture:** New `sources` table (`drive_id`, `path` relative to mount, `enabled`) + `media.source_id`. A new pure `dp-scan-detect` module inside `dp-jobs` (`detect.rs`) does a shallow media count per folder with the deny-list (`dp-core::denylist`). `ScanJob` iterates the drive's enabled sources (not the mount root) and tags rows with `source_id`; it emits `Progress{done:0,total:0,current:"Scanning <dir>"}` every 200 entries during the walk. `OrganizeJob` only plans rows with a non-NULL `source_id` (or legacy rows — see ruling). `RevertJob` moves `moved` items back with the same `MoveStrategy`. UI: a `SourcesDialog` on the Drives page (detect → confirm), a `DotLoader` (vendored MIT SVG from dot-matrix-animations) + step text in `ScanProgress`, a placeholder tile in the gallery for rows without thumbs, and "Revert" on Done/Dashboard.

**Tech Stack:** Rust (walkdir, sqlx), Tauri 2, React/TS, shadcn Checkbox/Dialog, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-22-drophoto-design.md` §5.0 (sources, deny-list, undo), §2.3, §7.

## Global Constraints

- All Phase 0–3 global constraints apply (pnpm; crate-per-capability; `src-tauri` wires; no unwrap/expect in non-test Rust; errors `{code,message,path?}`; components never import `@tauri-apps/*`; folder convention; coverage 80/75, `src/lib/**` 90; TDD; test output pristine; always shippable; conventional commits + trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`; issue #9, branch `feat/9-sources-safety`).
- **Deny-list (exact, case-insensitive on names):** absolute prefixes `/System /Library /Applications /usr /bin /sbin /private /opt /cores /Volumes/*/System` and `$HOME/Library`; directory names anywhere `node_modules .git $RECYCLE.BIN "System Volume Information" .Trashes .Spotlight-V100 .fseventsd Caches`; package suffixes `.app .photoslibrary .aplibrary .lrcat .lrdata .framework .bundle`; any hidden name (leading `.`). The deny-list applies to detection, scanning **and** organizing (a row whose current path is denied is never moved).
- **Stub rejection:** a file < 8 KB whose thumbnail decode fails is not inserted (skip with `ItemError{code:"stub"}`) instead of being catalogued.
- **Ruling on legacy rows:** rows scanned before this phase have `source_id = NULL`. They remain visible in the gallery; `plan_organize` excludes them (they must be re-scanned through a source first) and the Detect step shows "N files from older scans are not covered by a source — re-scan to include them".
- Revert is per job, moves only items with status `moved` whose file still exists at `new_rel_path`; refuses if `old_rel_path` is occupied (item `Failed`, nothing touched); logs as a new `organize_jobs` row with `kind='revert'`.
- Progress during the walk: `Progress { done: 0, total: 0, current: Some("Scanning <relative dir>") }` at most every 200 entries; UI shows the dot loader + current text while `total === 0`.

### Task 3.5.1: Deny-list + detection (pure Rust)

**Files:** `crates/dp-core/src/denylist.rs`, `crates/dp-jobs/src/detect.rs`, `crates/dp-jobs/tests/detect.rs`, `crates/dp-core/src/types.rs`

**Interfaces:**
```rust
// dp-core::denylist
pub fn is_denied_dir(abs: &Path, home: Option<&Path>) -> bool;      // prefixes + names + package suffixes + hidden
pub fn is_denied_name(name: &str) -> bool;
// dp-core types
pub struct DetectedFolder { pub rel_path: String, pub media_count: u64, pub bytes: u64, pub suggested: bool }
// dp-jobs::detect
pub fn detect_folders(mount: &Path, max_depth: usize /*4*/, cancel: &CancellationToken) -> DpResult<Vec<DetectedFolder>>;
// counts media (MediaKind::from_ext) per directory, aggregated up to the shallowest folder that holds ≥ 20 media OR is a top-level dir of the mount; sorted by media_count desc; `suggested` = count ≥ 20 || rel_path in {"", "DCIM", "Pictures", "Desktop", "Downloads", "Users/<name>/Pictures", …}. Root ("") is suggested only when ≥ 60% of counted media sits directly under it or in DCIM-like dirs AND the mount is not "/".
```
